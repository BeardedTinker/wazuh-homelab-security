# Security Policy

## Supported Versions

Only the **latest release** is supported with security fixes.

## Reporting a Vulnerability

Please **do not** open a public GitHub issue for security reports.

Use one of these options:

1. **GitHub Security Advisories (preferred)**
   - Go to the repository **Security** tab.
   - Open **Advisories** and select **New draft security advisory**.
   - If available, use **Report a vulnerability** for a private report.

2. **Email (fallback)**
   - Contact: inquiry@beardedtinker.com
   - Subject: `[SECURITY] wazuh-homelab-security`

Include:

- the affected release, tag, or commit;
- the affected rule, decoder, script, or configuration;
- the security impact and reproduction steps;
- sanitized logs or proof of concept;
- a proposed mitigation, if available.

Remove passwords, tokens, API keys, public IP addresses, internal URLs, hostnames,
usernames, device identifiers, and other private data before submitting material.

## Disclosure

We follow responsible disclosure:

- acknowledge receipt of the report;
- assess the impact and affected versions;
- develop and validate a fix;
- publish release notes or an advisory after remediation when appropriate.
